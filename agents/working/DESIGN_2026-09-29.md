## 5. Consent semantics

1. **Categories.** Built-ins: `necessary` (required, always granted), `analytics`, `marketing`,
   `functional`, `personalization`. `<category Name="video" Title="…"/>` adds one. A built-in
   can be retitled. Only `necessary` can be required.
2. **Scope by region.** The resolver gives a region, and the module places it in one mode:

   | Mode | When | Undecided categories | Banner |
   |---|---|---|---|
   | opt-in | the region matches `RequireConsentFor`, or the region is unknown (null) | denied until a choice | shown |
   | opt-out | the region matches `OptOutFor` | granted, except where GPC or a stored choice denies | not shown; `TConsentLink Mode="optout"` |
   | none | anything else | granted | not shown |

   `getIsConsentRequired()` is true in opt-in mode. With the default resolver, every visitor is
   in opt-in mode.
3. **getConsent()** returns category → `granted` / `denied` / `undecided`. `undecided` appears
   only in opt-in mode before a choice. `isGranted($category)` treats `undecided` as not
   granted.
4. **getIsDecided()** is true when a stored record exists whose `Version` equals the module's,
   or when the mode is not opt-in.
5. **Version.** A string such as `2026-09`. A stored record with another version counts as
   undecided. The store keeps it until a new choice replaces it, so the preferences can
   pre-fill the old answers.
6. **setConsent(array $categories, string $source)** normalizes the choice (unknown categories
   refused, `necessary` forced to granted), builds a `TConsentRecord`, saves it, logs it, and
   raises `onConsentChanged` when the effective consent changed. `acceptAll()`, `rejectAll()`
   and `withdraw()` (clear the store; log the withdrawal) call it.
7. **Expiry.** `Expires` (days, D3) applies to the cookie and to database rows. An expired
   record counts as undecided.
8. **GPC** (§8) is applied at read time and never written as a choice. The log notes whether the
   signal was present when a choice was made.

## 6. Storage schema

All times are Unix seconds (integers), read through the clock seam. Tables are created on first
use when `AutoCreateTables` is true (the default), as `TDbCache` does. Schemas for sqlite, MySQL
and PostgreSQL ship in `config/schema/`. With no `ConnectionID`, a module uses
`sqlite:<runtime>/privacy.db`.

### 6.1 Consent cookie (`TCookieConsentStore`)

- Name `prado_consent` (`CookieName`). Path `/`. `SameSite=Lax`. `Secure` on https. `HttpOnly`
  is on, because the server renders every decision. A property turns it off for a site whose
  scripts read the choice.
- Value: compact JSON, signed with `TSecurityManager::hashData()` whether or not the application
  enables cookie validation, so a forged cookie reads as undecided:
  `{"id":"9f…","v":"2026-09","t":1759150000,"c":{"analytics":1,"marketing":0,"functional":1,"personalization":0}}`.
  `necessary` is implied. About 200 bytes.
- The cookie stores a choice that the visitor asked for, so it is strictly necessary under
  ePrivacy Art. 5(3) and needs no consent itself.

writes to the runtime sqlite database, and a missing `pdo_sqlite` throws a
`TConfigurationException`. The README's GDPR setup section enables it.

Retention defaults, all configurable: log rows 3 years after the last change for the consent id
(the limitation period in most member states); request rows 3 years.

## 7. ganalytics integration

Mapping (documented in both READMEs):

| Category | Google consent types |
|---|---|
| `analytics` | `analytics_storage` |
| `marketing` | `ad_storage`, `ad_user_data`, `ad_personalization` |
| `functional` | `functionality_storage` |
| `personalization` | `personalization_storage` |
| (always) | `security_storage` = `granted` |

`undecided` maps to the key being absent, so ganalytics' `ConsentDefaults` applies. That is
ganalytics' existing contract. The reverse mapping, for `GAnalyticsModule::updateConsent()`
calls that arrive through `setConsentState()`, grants `marketing` only when all three `ad_*`
types are granted.

**The adapter goes in ganalytics, as `GAnalyticsPrivacyConsentProvider`.**

- The dependency points from the specific binding to the generic framework: ganalytics knows
  consent categories, and the consent framework knows nothing of Google. Putting it here would
  make a Google class part of a package meant for `pradosoft/prado`, which cannot ship it.
  When the proposal lands, the adapter would have to move anyway.
- The dependency stays optional both ways. ganalytics adds `belisoful/prado-privacy` to
  `suggest` and `require-dev` only. The adapter is loaded only when an application configures
  it (`ConsentProvider="privacy-analytics"`). prado-privacy never references ganalytics.
- The live update belongs there too: the adapter attaches to `TConsentModule::onConsentChanged`
  and calls `GAnalyticsModule::updateConsent()`, which closes ganalytics' deferred audit item.
- Advanced consent mode is the documented default (D1): the tag loads with the undecided types
  denied through `ConsentDefaults`, and the adapter's state overrides them. Basic mode stays
  documented as the alternative (`Enabled="false"` until consent); an adapter property to
  switch it automatically is a later ganalytics addition, not part of phase 4.
- The alternative, an adapter here implementing `IGAnalyticsConsentStore`, needs no ganalytics
  change today. It would put ganalytics into this package's `require-dev`, make the package
  standard checks load a class whose interface is absent in consumers without ganalytics, and
  move on the core proposal.

Phase 4 therefore edits `../prado-ganalytics` (its own branch and commit, with approval) and adds
the mapping and an advanced-mode configuration example to this README.

## 8. Global Privacy Control

`Sec-GPC: 1` (`THttpRequest::getHeader('Sec-GPC')`). Recommended handling by mode (D4):

| Mode | Legal footing | Effect of GPC |
|---|---|---|
| opt-out (`US-GPC`: California, and the states whose laws require honoring a universal opt-out signal: Colorado, Connecticut, Delaware, Maryland, Minnesota, Montana, New Hampshire, New Jersey, Oregon, Texas; the list must be checked against current law at release) | binding: CCPA regulations §7025 treat it as a valid request to opt out of sale and sharing; the state laws do the same for sale and targeted advertising | `marketing` denied, overriding a stored grant. A later explicit grant of `marketing` in the preferences wins, as §7025(c)(3) allows, and the log records it. `TConsentBanner` can show "Opt-out preference signal honored" (§7025(c)(6), optional) |
| opt-in (EU, EEA, UK, CH, unknown) | not a consent signal under ePrivacy; an objection by automated means is foreseen in GDPR Art. 21(5) | `marketing` starts denied and the banner says so. Accept-all grants every other category and leaves `marketing` denied. Only a grant of `marketing` in the preferences overrides the signal |
| none | no obligation | the same as opt-out (`HonorGpc="everywhere"`, the default). `HonorGpc="required"` limits it to the opt-out regions. `HonorGpc="off"` ignores it |

The brief listed US-CA under `RequireConsentFor`. CCPA/CPRA is an opt-out regime, so this
design puts California in `OptOutFor` (the `US-GPC` group). Listing it under `RequireConsentFor`
still works: Californians then get the opt-in banner, which the law allows (D5).

### 8.1 Locating the visitor by IP address

The owner asked for a seam that lets an application or another extension take the visitor's IP
address and decide whether a banner is needed, with free services optional and the commercial IP
intelligence APIs reachable.

**Flow.** `TConsentModule` asks its `IRegionResolver` once per request, and the result is cached
on the module. `TIpRegionResolver`:

1. Takes the client IP. `REMOTE_ADDR` by default. `TrustedProxies` (CIDR list) lets it read
   `X-Forwarded-For` or `Forwarded` from those hops only, because PRADO's
   `getUserHostAddress()` has no proxy handling. Private, loopback and reserved addresses resolve
   to null (unknown) without a lookup.
2. Looks in the cache: `CacheID` (any `ICache` module, default the application cache if one is
   configured), keyed by an HMAC of the IP, with `CacheExpire` of 1 day by default. Misses are
   cached too, for a shorter time.
3. Calls its `IIpLocator` (`Locator="moduleId"`, `<locator class="…"/>`, or an instance).
4. Maps the `TIpLocation` to a region (`US` + `CA` → `US-CA`).

On any failure (a timeout, a quota response, a malformed body) the result is null, which is
opt-in mode. The resolver fails closed: a visitor it cannot place sees the banner. A failure is
logged under the resolver's class at `TLogger::WARNING` and never thrown to the page.

`TChainRegionResolver` combines resolvers: a CDN header first (free, no lookup), then a local
database, then an API.

**Locators shipped.**

| Locator | Covers | Notes |
|---|---|---|
| `TMaxMindDbLocator` | any MaxMind DB format file: MaxMind GeoLite2 (free, account and licence key), MaxMind GeoIP2 (paid), DB-IP IP to City/Country Lite (free, CC BY 4.0, attribution required), IPinfo's free country database, IP2Location's mmdb editions | local lookup, no transfer of the IP to a third party, sub-millisecond. Needs `maxmind-db/reader` (suggested). The file is refreshed by the operator or a cron job; the class only reads it |
| `THttpIpLocator` | any JSON API | `Url` template (`https://…/{ip}?key={key}`), `ApiKey`, `AuthHeader` (for bearer-token APIs), `CountryPath` and `SubdivisionPath` (dot paths into the JSON), `Timeout` (1.5 s default) |

`THttpIpLocator` presets by `Service`, which fill in `Url` and the paths:

| `Service` | Provider | Free tier (to verify at release) |
|---|---|---|
| `maxmind` | MaxMind GeoIP2 Precision web services (Country, City, Insights) | none; per-query pricing; basic auth (account id, key) |
| `ipinfo` | IPinfo (`ipinfo.io/{ip}/json`, and the Lite API) | Lite: country level, free with a token |
| `ipdata` | ipdata.co | about 1,500 requests/day |
| `ipgeolocation` | ipgeolocation.io | about 1,000 requests/day |
| `ipregistry` | Ipregistry | trial credits |
| `ipapi` | ipapi.co | about 1,000 requests/day |
| `ipstack` | ipstack (apilayer) | small monthly quota, no https on the free plan |
| `ip2location` | IP2Location.io | about 30,000 requests/month |
| `abstract` | Abstract API IP geolocation | small monthly quota |
| `bigdatacloud` | BigDataCloud | client-side free; server side needs a key |
| `dbip` | DB-IP API | free tier for small volumes |

Not shipped as presets: `ip-api.com`, whose free endpoint is plain http and restricted to
non-commercial use. Any other API works through `Url` and the paths without code.

Adding a service is a new `IIpLocator` in the application or another extension. Nothing in this
package changes. An extension can also ship a whole resolver and attach it with
`dyResolveRegion`.

**Privacy of the lookup itself.** Sending a visitor's IP to a third party is a transfer of
personal data. It happens before any consent, on the basis of legitimate interest or legal
obligation (deciding which law applies). The README says so, recommends a local database or a CDN
header first, and lists the lookup in the records-of-processing registry
(`TIpRegionResolver` implements `IProcessingActivityProvider`). The cache key is an HMAC, so the
cache never holds IP addresses in clear.

**Tests.** `THttpIpLocator` runs against `LocalHttpServer` (PHP's built-in server on the loopback
serving canned JSON per preset), the same pattern as ganalytics' transport test. `TMaxMindDbLocator`
reads a small `.mmdb` test fixture built in the repository (MaxMind publishes test databases
under an open licence, and `tests/fixtures/` would hold one). Its tests skip when
`maxmind-db/reader` is absent, which CI avoids by installing it as a dev dependency.

## 11. Legal notes that constrain the code

These are engineering readings, not legal advice. The README says the site owner remains
responsible for its policy text and category choices.

- Reject-all must be as easy as accept-all, on the first layer (EDPB cookie banner taskforce
  report, 2023; CNIL). The banner renders both as the same element type with the same CSS
  class. There is no pre-ticked box (CJEU C-673/17 *Planet49*).
- Withdrawing must be as easy as giving (Art. 7(3)). `TConsentLink` is meant for every page's
  footer, and the README says so.
- The banner makes no claim that "legitimate interest" covers analytics or advertising cookies.
  ePrivacy consent does not accept that basis.
- A cookie wall is out of scope. `TConsentGate` gates content per category and never blocks the
  page.

## 12. Implementation notes (phase 1, 2026-09-29)

What the code settled that the design above left open:

- `IConsentControl` (`refreshConsent($writer)`): every consent control registers with the
  module in `onInit`; a callback re-renders all of them through `refreshConsentControls()`. Each
  control wraps its output in one `TActivePanel` (the gate is one).
- `TConsentLink::PreferencesUrl`: a link button needs JavaScript, so the link carries a real
  `href` to a settings page (`TConsentPreferences AlwaysVisible="true"`); with JavaScript the
  callback runs instead.
- `TPrivacyHash` (HMAC-SHA256 with the validation key, a purpose label per use) serves the log,
  the database store and the IP cache.
- `TPrivacyActiveRecord::on($connection)` binds finders and found records to the component's own
  connection (`TPrivacyDbConnectionTrait`: `ConnectionID`, or `runtime/privacy.db`).
- `TConsentRecord` carries its expiry, so stores need no module reference; `IConsentStore`
  is `load()/save(TConsentRecord)/clear()`.
- `IConsentLog` gained `findByConsentId`, `findBySubject` and `purge`, for rights (phase 2) and
  retention (phase 3).
- `THttpTransportTrait` lives in `Consent\Region` (its only user so far).

## 13. Implementation notes (phase 2, 2026-09-29)

- `TPrivacyModule` runs providers under `runRequest()`: the request is opened in the log, the
  providers run with exceptions caught per provider (the message goes to `Prado::log`, only the
  class to the record), and the status is `completed`, `partial` or `failed`.
- `IPrivacyRequestLog` is `open()/complete()/find()/findBySubject()/findPending()/purge()`;
  `openRequest()` lets an application record requests received outside it.
- The built-in providers are modules (so they are discovered when configured as modules) and can
  also be listed with `<provider>`. `TUserPersonalDataProvider` resolves the user manager from
  `UserManager`, the first `TAuthManager` (whose manager is a module id until it initializes), or
  the first `IUserManager` module.
- `TDbConsentStore` gained `findBySubject()` and `deleteBySubject()` for the consent provider.

## 14. Implementation notes (phase 3, 2026-09-29)

- `IConsentLog` and `IPrivacyRequestLog` extend `IRetentionPurger` (their `purge()` already had
  its signature), and `TDbConsentStore` implements it for expired rows, so the built-in policies
  need no adapter classes.
- Built-in policy names: `consent-log`, `consent-state`, `privacy-requests`, taken from the
  first module of each type. Activities reference them by name.
- Declarations: modules implement `IProcessingActivityProvider`; other components answer the
  global event `fxGetProcessingActivities` (modules auto-listen as `TApplicationComponent`s). The
  registry lists an identical declaration once (a resolver can be both a module and the consent
  module's resolver) and refuses two different activities with one name.
- `TPrivacyShellAction::register()` is shared by the three modules; the commands find the
  retention module and the registry by type.

## 15. Implementation notes (phase 4, 2026-09-29)

- The adapter is `GAnalyticsPrivacyConsentProvider` in belisoful/ganalytics (D9), a module that
  implements `IGAnalyticsConsentStore`. prado-privacy is unpublished, so ganalytics cannot take
  it even as a dev dependency. The provider therefore finds the consent module by its surface
  (`getConsent()`, `setConsent()`, `onConsentChanged`) and binds those two methods as closures,
  which also keeps PHPStan honest without suppression. Neither package references the other's
  classes. ganalytics' tests use a fake module with that surface; the binding was also verified
  locally against the real `TConsentModule` (mapping, live update, no write-back loop, write-back
  of `updateConsent()` as an `api` choice).
- Loop guard: a change forwarded to `GAnalyticsModule::updateConsent()` would come back through
  `setConsentState()`; the provider ignores it while forwarding.
- Advanced consent mode is the documented default (D1). An automatic basic-mode switch is a later
  ganalytics addition.
- ganalytics: the work on its `main` is its next release, 0.2.0 (only v0.0.1 is tagged; the
  owner names v0.1.0 as current), so the adapter carries no `@since` and joins the `[Unreleased]`
  notes; `belisoful/prado-privacy` is in its `suggest`. prado-privacy's first release is 0.1.0.
